# Citation retention and archive cleanup

The source retention job compacts expired cited rows to URL/title/domain/snippet/hash/date metadata, preserving signal/summary join rows. Uncited expired sources are removed in batches of500 with row locks. Existing plan retention windows remain30/90/180/365days. Summary citations live as long as summaries; compacted stubs are rehydratable by later successful scrapes.

Migration0023 creates an object cleanup registry independent of project/user FKs. A source trigger queues displaced/deleted archive keys and removes unclaimed upload reservations on attachment. Uploads use UUID keys and reserve a one-day delayed orphan job before any provider call. Once deletion has started, a key cannot be reattached—even after failure or completion. Completion tombstones intentionally persist to enforce this invariant. Successful source rows exclude their referenced objects from claims. Cleanup claims at most10 objects, uses15-second request timeouts, and backs off failed operations up to24hours. Disabled storage preserves queued work. There is no bucket-wide sweep or automatic deletion of unknown legacy keys.

`node --test tests/storage/cleanup.test.cjs` uses synthetic SQL/provider modules to verify disabled behavior, retry acknowledgment, reference exclusion, path restrictions, orphan reservation and key uniqueness. Independent disposable PostgreSQL verification is required for triggers, cascades and claim/attachment concurrency. Never run retention tests on customer data.
