# IFY-017 — publisher URL extraction

Base: `6687bc9`. Real demo SERP results used `https://google.com/goto?url=CAES...` with opaque tokens. Their publisher cannot be decoded by this local helper. Only wrappers containing explicit HTTP(S) destination URLs can be resolved here; opaque demo provenance remains unresolved.

`serpPublisherUrl` now unwraps only exact `google.com` / `www.google.com` hosts at `/goto` (`url`) and `/url` (`url` or `q`). It accepts exactly one destination parameter and decodes the enclosing query once via URLSearchParams. Destination path case, meaningful query parameters, repeated query values and percent-encoded article components are preserved. Existing source normalization subsequently handles ordinary deduplication. Observed `/goto?url=CAES...` base64url-shaped opaque tokens are preserved as unresolved Google wrappers before top-N selection. They still display Google identity; no article publisher is inferred. Invalid/unsafe/ambiguous/nested explicit destinations are omitted. Publisher URLs and Google-looking foreign hosts are never treated as trusted redirect wrappers.

The existing `safeSocialUrl('website')` policy supplies HTTP(S), credentials/port/whitespace and length checks plus HTTPS canonicalization. No stronger reusable public-HTTP policy existed at this base. The source-only helper adds absolute URL, malformed-escape, backslash, literal-IP and local/reserved-hostname exclusions. It does not weaken or alter the shared validator. No DNS lookup or redirect following occurs here; DNS rebinding and arbitrary publisher redirect-chain safety remain fetch-boundary concerns. Host recognition is deliberately limited to these two Google hosts, not a regex over arbitrary country domains.

Validation: six focused regression tests pass, including the actual `serpDiscover` module with mocked provider response, publisher domain/canonical identity, plain Google goto/url shapes, the exact opaque demo token retained in actual SERP extraction, meaningful queries, double encoding, unsafe/private/malformed/nested destinations and ambiguous parameters. `npm run typecheck` passes. Prior plain-wrapper increment full suite: 313 passed, one existing integration test skipped; this bounded opaque-token correction reran the six focused tests and typecheck. No real provider calls, data writes, migrations or destructive backfill. Existing stored wrapper rows and historical citations remain unchanged; original discovery wrappers are not stored in a new field in this bounded change.

Rollback: revert the code commit; already stored publisher URLs remain compatible with current source normalization and scraping.

Recognized tokens use the observed `CAES` prefix and at least 20 subsequent base64url characters; the exception applies only to exact trusted Google `/goto` hosts/paths, never arbitrary schemes, nested URLs or other redirect hosts. No network decoder or redirect expansion was added. Original public-URL limits still apply.
